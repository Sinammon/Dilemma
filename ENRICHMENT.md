# Vehicle evidence and the school demo

The app uses live seller data, optional original VIN records, reviewed factory power references, bundled Canadian fuel reference data, a reviewed model-opinion library, and optional Gemini web research for missing typical-model specifications. Sourced single values can enter comparisons and category rankings; ranges and optional equipment remain context. Comfort uses cited refinement dimensions rather than equipment counts.

## Automatic specifications (31 October 2026)

`POST /api/model-specs` is shared by the local Node server and Vercel. `shared/model-specs.js` defines the configuration/field contract. Only year, make, model, known configuration details and requested missing fields are accepted for research; other listing fields are discarded. The API retains existing JSON, same-origin, byte-limit and no-store behavior. Invalid requests return 400; provider outages return an unavailable result without leaking credentials or upstream bodies.

`phase: "quick" | "research"` selects staged lookup; omission retains research behavior. Listing/reference/cache values appear immediately and VIN decoding runs independently. Quick lookup is tool-free and limited to missing core specs, with an eight-second total deadline. Research verifies and improves fields in the background within forty seconds. The provider and billing configuration are unchanged. A shared deadline includes at most one transient retry per phase. Daily quota/authentication/invalid requests stop, while short provider retry delays are honored. Browser transport retries do not repeat a returned provider failure.

Source-backed values retain successfully retrieved, approved source URLs and unit-bearing quotes. A single credible source can support a compatible **Typical model spec**; manufacturer-backed exact applicability may be a **Factory reference**. Unconfirmed nonessential trim/market details retain explicit assumptions, actual source year and configuration. Known engine/body/transmission contradictions, gross/dry weights and acceleration conversions remain rejected. **Estimated model specs** are bounded, unverified core values with assumptions and no invented citations. M Sport does not select an M engine variant.

Fields merge by evidence strength. Listing details win over conflicting VIN and reference values; compatible VIN data supplements only missing fields. Internal listing contradictions still block matching. Typical and estimated power/weight are eligible for provisional results, while Comfort still requires applicable professional reviews. `src/bundled-model-specs.js` supplies the reviewed BMW Z3 2.8 automatic coupe fallback, including its adjacent-year weight definition.

The browser model-spec cache excludes all imported listing/seller data, VINs, mileage and prices. It stores up to 200 normalized configurations, retains source-backed results for 30 days and estimates for seven, and permits visibly stale outage recovery up to 90/30 days. Configuration is revalidated on reuse. Storage failures fall back to memory; clearing the cache prevents in-flight work from repopulating it. Shortlists remain temporary. See [SPEC_RELIABILITY.md](SPEC_RELIABILITY.md) for details and measured checks.

`enrichment.modelSpecs` also returns up to 18 validated model insights, category assessments, checked time and successfully read sources. Insights cover value, affordability, comfort, balanced use, practicality, performance, safety equipment, strengths and documented issues. General model observations can omit trim-specific scope, but may not contradict a known configuration or silently select an unknown variant. Editorial observations are attributed. Owner anecdotes, unsupported reliability/frequency claims, insurance claims and fabricated monetary savings are rejected. Assessments include every applicable validated observation, so the model cannot omit a drawback from scoring citations.

Broad favourable/mixed/unfavourable assessments remain readable for older responses but add no numeric points. Validated `dimensionRatings` supply applicable professional-review scope, rationale, 0-5 rating and editorial citations for ride, quietness, front/rear seats, front/rear space and cargo space. Manufacturer marketing cannot supply these ratings. An exact-year/body/variant reviewed Maybach S 680 reference supplies ride and quietness context when retrieval fails; live applicable ratings take precedence, and seating/space remain unknown in the reviewed reference. Performance adds `curbWeightKg`, `zeroTo100KphSeconds` and `zeroTo60MphSeconds`; acceleration retains factory-versus-instrumented measurement method. Gross/dry weights, incompatible configurations and acceleration conversions are excluded.

[DECIDE_REDESIGN.md](DECIDE_REDESIGN.md) defines category weights, shared capability, the Best Value/Balanced distinction, coverage and provisional results. Eligible contenders share supported factors. Unsupported cars remain unranked; no category falls back to another priority. Model refinement can rank without advertised gadgets. Purchase concerns remain visible and separate from scores: seating mismatches cannot demote comfort, while serious mechanical concerns mark a category leader review required. Contradictory listing configuration/identity remains excluded; VIN differences stay secondary.

`enrichVehicle` publishes VIN/factory/fuel results while research runs. Per-car retry works without eBay reimport, aborts older work and preserves previous research if a retry fails. Removing/replacing a car or clearing the comparison prevents late results from returning. The demo makes no AI calls and uses the reviewed library. Imported listings remain temporary; only sanitized model-spec references may persist in the device cache.

Setup uses a backend-only `GEMINI_API_KEY` from a Free Tier project with billing unlinked. Restart after saving `.env`; existing processes do not reload it. Distinct statuses cover not-configured, model-unavailable, quota, timeout, no-sources, partial and matched results. A valid key is configured locally and the restarted HTTP endpoint has been tested; credentials are never logged or exposed to the frontend.

The evaluator combines 30 independently checked NRCan configurations with nine manufacturer power references and separately reviewed model observations. Numeric precision and population coverage are reported separately; category coverage does not measure semantic accuracy. The main journey tests pending research, category scoring, retry failure preservation and cancellation. Rendered React tests run locally; native browser verification was blocked by the browser access host being unavailable and the selected Chrome window being minimized. No new desktop/mobile visual approval is claimed.

Validation on 30 October 2026: all 105 automated tests and the production build passed. After restarting the local backend, an HTTP lookup for the Canadian 2018 Civic LX 2.0L six-speed manual returned 158 hp, 187 Nm, five sourced insights and assessments for all six categories. The broader live run attempted all 39 reference configurations: 14 of 104 requested numeric fields were populated, and all 14 matched their independent references (13.5% coverage; no mismatches among populated fields). This small populated sample does not establish general accuracy, and broad coverage remains limited by source retrieval, corroboration and configuration matching. No measured or unmeasured accuracy percentage is advertised in the UI.

Model-observation audits compare live output with the independently reviewed Civic, Corolla, Mazda3, Thunderbird and Sprinter profiles. They are a manual source/scope check, not a semantic-accuracy benchmark. Conditional infotainment, safety and engine-option comments found during the audit are now explicitly context only, excluded from assessments, main reasons and test-drive suggestions. The full run preceded this extra insight-only filter, so its category counts are not presented as current scoring coverage. Numeric source/parsing rules were unchanged. The current-code HTTP test above was run after that filter. No live eBay import, hosted deployment or new browser visual sign-off is claimed.

## What works

Follow-up fix: live Gemini insight IDs can contain underscores; those valid IDs were previously rejected. Evidence now carries the exact candidate URL as well as an ID, so a misnumbered ID can be resolved to a successfully retrieved URL. An invented or unread URL is still rejected. Ford F150 source routes are normalized separately for Edmunds (`f-150`) and KBB (`f150`), with an additional independent Cars.com specification seed. Optional scope properties no longer require repetitive null placeholders, and output prioritizes supported specifications and eight concise insights.

Compatible source-backed single values now use quality `typical` with explicit assumptions and can contribute to provisional results. Ranges and alternatives remain context, and known configuration contradictions are rejected. Scoped review notes retain their existing context restrictions.

Successful results show their specification/note counts, a **View results** control that opens the correct vehicle disclosures and moves keyboard focus, and **Refresh research**. **Retry research** is reserved for failures. Local HTTP tests through Vite and the actual browser-side response validator returned results for the 2005 BMW X5 (8 specifications/5 notes), 2022 Ford F-150 (5/6) and 2013 Hyundai Elantra (7/5), in approximately 19–23 seconds. Some fields, including torque in that run, remained unsupported. Counts vary with source retrieval. All 108 tests and the production build passed. The earlier 39-configuration precision result above predates these parser changes and is not a measurement of the updated implementation. Native visual interaction remained unavailable (`coordinate input geometry is unavailable`); disclosure opening and focus were verified in rendered React tests.

`enrichVehicle` runs after import and never blocks showing a listing. VIN checks and local fuel-file loads have bounded timeouts. Outages leave seller data usable. Removed/replaced cars cannot be restored by late responses. Neither the new research library nor the demo writes listing payloads to disk, browser storage or a database.

The fuel matcher now understands the explicit NRCan Mazda3 `4-Door`/`5-Door` naming when supported sedan/hatchback evidence is present. It does not strip configuration suffixes, infer trim, assume equipment or choose a nearby model. An ambiguous Corolla CVT remains unmatched.

## Basic specifications (30 October 2026)

Mileage selects the first attached number/unit in the seller description, then title, then structured fields. Supported formats include comma/space grouping, `120k km`, `120kms`, `2k kms`, miles and HTML entities. No conflicting-statement or unrelated-distance reconciliation is performed, as requested. With no attached-unit reading, the first labelled or parseable structured reading uses an explicit declaration or defaults to kilometres. No reading remains unknown. Original imported records stay unchanged, and selected evidence/source plus any kilometre assumption remain visible. Miles convert to kilometres for scoring only.

Power extraction supports horsepower prose, kW/PS, common lb-ft/Nm spellings, and unit-bearing structured or prose labels. Evidence retains source quotes. Converted power/torque values within 0.75 canonical units are treated as rounding agreement; larger differences stay conflicting. Bare `Power: 200` and `Torque: 200` still lack a supported unit.

`enrichVehicle` adds `factorySpecs` independently of fuel results. It returns `matched`, `insufficient`, `unmatched`, `ambiguous`, `conflict` or `unavailable`, with a reason and missing discriminators when applicable. Factory lookup failure leaves seller data usable. Matched values enter the shared extractor and supported decision factors; source labels say factory reference, not measured output. Existing weights and missing-factor safeguards remain unchanged.

Initial reviewed coverage: Canadian 2018 Civic sedan 2.0 manual/CVT and 1.5 CVT (excluding Si/Type R); Canadian 2019 Corolla CE/LE/SE and LE ECO CVT sedans; Canadian 2017 Mazda3 sedan/Sport 2.0 and 2.5; US 2002 Thunderbird 3.9 automatic and 2005 Dodge Sprinter 2.7 diesel automatic. Other markets, years and configurations remain unsupported. Manufacturer references and document locators are recorded beside each row. The fictional demo now explicitly specifies Canadian market and Corolla LE trim, so all three cars receive factory power references after enrichment. Comfort remains a sparse-data fallback; Performance can use factory power and torque.

Regression coverage is in `basic-specs.test.mjs` and the full rendered Import/Compare/Decide test. Browser visual verification for this update was blocked by Computer Use's browser-URL validation; no new desktop/mobile visual claim is made.

Each claim has a category, source IDs and wording reviewed on 29 October 2026. Each source has a publisher, specific title, HTTPS URL, section/page locator, source type and review date. A claim with missing or unresolved citations is withheld. Citation validation checks identification; human review is still needed to establish that the source actually supports the wording.

Profiles cover strengths, documented issues, comfort, practicality and performance. Reviews are attributed opinions about typical/tested configurations. Bulletins and recalls support issues to investigate, not failure-frequency statistics, a reliability score, Canadian warranty eligibility, an individual diagnosis or an open-recall lookup. The reviewed opinion library cannot establish installed equipment and does not populate specifications. Separately validated live specification findings can fill unknown fields, with provenance.

To expand the bundled review library, read supporting sources first, add a narrowly scoped profile with claim-level citations, and add scope/regression tests. Do not broaden a year range because the name looks similar. The separate live Gemini integration now extracts attributed review observations as well as specifications, with retrieval, citation and configuration checks. It cannot establish history or current condition. The separate free NHTSA campaign lookup does not answer individual condition or installed-equipment questions.

## Repeatable demonstration

1. Start the frontend with `npm run dev`. The backend (`npm run server`) is needed for live eBay, VIN, recall and Gemini requests; the fictional demo works without it.
2. Click **Try fictional demo** on Import or an empty Compare page. It loads three invented vehicle records in memory. It makes no eBay, VIN or research request; fuel data comes from bundled public files served by Vite.
3. Compare the key table and the four evidence categories. Civic and Mazda3 have unique fuel matches; Corolla's incompletely specified CVT has multiple possible matches, so it gets no rating. This also excludes fuel from all-car cost scoring.
4. Open **Typical model research** to show all five topics and identifiable sources. Source links need internet if clicked; the summaries themselves work offline.
5. Choose **Help Me Decide → Performance**, then **Comfort & Features**. After enrichment, Performance compares manufacturer factory horsepower/torque references, with citations and the factory-output limitation. Comfort has no scored refinement dimensions in the bundled demo, so it shows guidance without a substitute price-based winner. A relevant positive review can suggest a test drive; it does not establish superiority over uncovered cars.
6. Switch to **Best Value** to show the numeric price/age/mileage result, advantages, trade-offs, source labels and excluded factors. Refresh to clear the demo.

The demo is always explicitly labelled fictional. It does not impersonate real eBay listings, use real eBay listing photographs, or claim a VIN decode took place. Bundled Commons model-example photos have linked credits and may differ from the fictional year, body or trim.
